How SPROUT is built

Four parts: a vision model trained on a GPU, a search engine over 237 extension guides, a question engine that keeps every number in code, and a small web stack that serves it all.

The system

A static site, one Python server, and an AI model that only writes text.

The vision model

ConvNeXt V2 Tiny, fine-tuned on 19,260 photos: 12,918 from the lab and 6,342 taken in fields and gardens.

The guide search

Every question, piece of advice and chat reply starts from passages in 237 university extension guides.

The question engine

The AI model writes the words. Code does the counting, so the same answers always give the same result.

Built with

Python end to end, from data checks to the server; plain HTML, CSS and JavaScript for the site.

Training

  • PyTorch and timm, ConvNeXt V2 Tiny pretrained on ImageNet-22k
  • AdamW, batch size 32, 224 px inputs, fresh lab and field mix every epoch
  • CUDA mixed precision on an RTX 4070 laptop GPU

Data

  • Five public datasets: PlantVillage, PlantDoc, PlantSeg, PlantWild, Plant Pathology 2021
  • Perceptual hashing and DINOv2 similarity to keep near-duplicates out of the test set
  • DVC for versioned datasets, pandas manifests for every split

Evaluation

  • Macro-F1, top-3 accuracy, bootstrap confidence intervals, McNemar’s test
  • Temperature scaling and expected calibration error
  • MLflow for every run; each published number traced to a run record

Serving

  • ONNX export, served by ONNX Runtime on CPU
  • Flask API with a background thread pool and per-visitor spend caps
  • Photos read with Pillow, turned upright, never stored

Search and text

  • pypdf extraction, passages tagged by crop and disease
  • BM25 plus BGE-small embeddings via fastembed, MiniLM cross-encoder reranker
  • An AI model API for questions, advice and chat, checked by code

Quality

  • About 950 automated tests with pytest
  • Ruff linting and GitHub Actions on every push
  • This site: hand-written HTML and CSS, inline SVG diagrams, no framework
